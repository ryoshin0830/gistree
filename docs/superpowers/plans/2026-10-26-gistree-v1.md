# gistree 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PoC（`poc` ブランチ）の挙動を main に作り直す。あわせて `.json` を使った軽い取得、DOM テスト、セレクタを監視する CI、アイコン、自動リリースを加える。

**Architecture:** MV3 の content script（`src/lib.js` → `src/content.js`）と CSS で構成する。純粋な関数と `SEL` は `src/lib.js` に置き、Node のテストと監視スクリプトからも読む。DOM テストでは jsdom の window に 2 つのファイルをそのまま `eval` し、`fetch`・`IntersectionObserver`・`matchMedia` だけを差し替える。

**Tech Stack:** Chrome MV3、素の JS/CSS、Node 22 の `node --test`、jsdom（devDependency）、GitHub Actions、`gh`

**Spec:** `docs/superpowers/specs/2026-10-26-gistree-v1-design.md`

## Global Constraints

- permissions と host_permissions は空のまま。`api.github.com` を呼ばない。token を求めない。
- 拡張にビルド工程を設けない。`manifest.json` が `src/lib.js`、`src/content.js`、`src/gistree.css` を直接読む。
- manifest の `"version": "1.0"`。リリース時の version は `1.0.<git rev-list --count HEAD>`、tag は `v<version>`。
- 取得や解析に失敗したら、その部分は GitHub の表示のままにするか、行・右欄にメッセージを出す。例外でページ全体を壊さない。
- UI の文言は英語。色は Primer の CSS 変数を使う。ポインタで操作するコントロールの高さは 28px。
- PoC の参照元：`git show poc:src/content.js`（`lib.js`、`gistree.css`、`test/lib.test.js` も同様）

## Review Focus

1. 自分の secret gist の `.json` が、ログイン中に取れること。テストでは確かめられないので、Task 7 で実機で確認する。
2. ファイル名が `.json` の `files` と `div` 内の `div.file` で数がずれたとき。少ない方に合わせ、例外を出さない（Task 3 のテスト「mismatched json」）。
3. 選択の取り違え。A を選び、取得中に B を選んだら、右欄は B のままであること（Task 3 のテスト「stale selection」）。
4. Turbo キャッシュから戻ったとき、索引とサイドバーが二重にならず、操作も効くこと（Task 2・3 のテスト「turbo restore」）。
5. 監視 CI の誤報。discover の先頭の gist が 1 ファイルでも、通ること（Task 4）。

### Task 2: jsdom ハーネス、個別ページのサイドバー

- Produces: `test/dom.js` の `load({ url, html, fetchMap = {}, wide = true }) -> window`

  - `src/lib.js` と `src/content.js` を `window.eval` する。

fixture は実際の gist ページの構造を写す。`.gist-content` の中に `.js-gist-file-update-container > div.file#file-<slug>` を 3 つ置き、それぞれに `.file-info svg`、`.gist-blob-name` を持たせる。中身は合成したもの。

### Task 6: CI と自動リリース

**Files:**
- Create: `.github/workflows/ci.yml`

`ci.yml` は次の形にする。
- トリガー：`push`（全ブランチ）と `pull_request`
- `test` ジョブ：`actions/checkout@v4`、`actions/setup-node@v4`（`node-version: 22`、`cache: npm`）、`npm ci`、`npm test`
- `release` ジョブ
  - 条件：`needs: test` かつ `if: github.event_name == 'push' && github.ref == 'refs/heads/main'`
  - 権限：`contents: write`
  - checkout は `fetch-depth: 0`
  - version：`v=$(jq -r .version manifest.json).$(git rev-list --count HEAD)`
  - tag がすでにあれば終了する。
  - `dist/` に、`jq --arg v "$v" '.version=$v'` で書き換えた manifest と、`src`、`icons` を置く。
  - `(cd dist && zip -r ../gistree-$v.zip .)` で zip を作る。
  - `gh release create v$v gistree-$v.zip --target $GITHUB_SHA --generate-notes --title "gistree $v"` で Release を作る。

- [ ] **Step 1: 確かめる。** `actionlint`（あれば）か、YAML の構文チェックを通す。release ジョブの手順をローカルでも実行し（`gh release create` は除く）、zip の中身を `unzip -l` で確かめ、manifest の version が `1.0.N` になっていることを見る。
- [ ] **Step 2: コミットする。** `ci: test on every push, release a zip on every push to main`
