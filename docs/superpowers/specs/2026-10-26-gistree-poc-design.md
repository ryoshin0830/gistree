# gistree PoC 設計

## 何のために

gist.github.com では、複数ファイルの gist でも一覧には「ASCII 順で先頭の 1 ファイル」しか出ない。そのため、どの gist に何個・どんな名前のファイルがあるか分からない。個別ページでもファイルの全体像がつかみにくい。gistree はこの 2 つを Chrome 拡張で直す。

## ゴール

1. **一覧ページ**（`.gist-snippet` があるページ：ユーザー一覧、starred、discover、検索）
   - 各 gist のカードを 2 列にする。左が全ファイルの一覧、右がプレビュー。
   - プレビューの選び方：`README.md` → 他の `.md` → `.txt` → 先頭ファイル（GitHub の表示順）。
   - ファイル一覧は全件表示する。省略しない。
   - ファイル名をクリックすると、個別ページの該当ファイル（`#file-…`）へ飛ぶ。
2. **個別ページ**（`.gist-content` の中に `div.file` があるページ）
   - 左にサイドバーを出す。中身はファイル一覧、絞り込み欄、現在地のハイライト。
   - サイドバーは隠せる。初期状態は表示。開閉の状態は localStorage に保存する。

## 非ゴール（PoC ではやらない）

- 並べ替えの保存、Firefox/Safari 対応、ストアへの公開、オプション画面
- 30 件を超えたときに折りたたむかどうか（ユーザーと相談中のまま）

## アンチゴール

- **トークンや API キーを要求すること**（ユーザーの指定）。GitHub API は使わない。
- 読み取りに失敗したときに GitHub の元の表示を壊すこと。失敗したら何もしない。

## 制約と決めたこと

- データは gist.github.com から、同じサイトの gist ページの HTML を `fetch` して `DOMParser` で読む。ログイン中の Cookie がそのまま使われるので、自分の secret gist も見える。
- 同時に読み込むのは最大 3 件まで（429 を避けるため）。
- 見た目は GitHub 純正に合わせる（Apple HIG の「プラットフォームに馴染む」）。
  - 色は Primer の CSS 変数を使う。ライト/ダークは自動で追従する。
  - アイコンは、読み込んだページにある Octicon をそのまま流用する。
- 長いファイル名は真ん中を省略する。先頭と拡張子を残し、`title` にフルネームを入れる。
- 幅 768px 未満では縦積みにする。
- ビルドツールもフレームワークも使わない。MV3 + 素の JS + CSS。

## 実装担当の判断に任せたこと

- プレビューの高さ（PoC は 240px 程度で、下をフェードさせる）
- 現在地を判定する IntersectionObserver の閾値

## v2：一覧ページを「索引」にする（2026-10-26 追記）

ユーザーが拡張機能を試した結果、まだ見づらかった。原因は次の 5 つ。

1. 一覧なのに「読む」作りになっていた（10 件で縦 5,653px）
2. 1 ファイルの gist は元のままで、見た目が揃わない
3. 太字の見出しが「ASCII 順で先頭のファイル名」で、説明文が埋もれる
4. GitHub 検索は `user:<login>` を付ければ secret gist も本文から探せるのに、入口が無い
5. 22 件が 3 ページに分かれ、全体を見渡せない

対応として、一覧を次の形に変える。

- 1 件 = 1 行のまとまり：見出しは説明文（無ければ GitHub のタイトル）、Secret ラベル、更新日、全ファイル名のチップ。プレビューは `<details>` の三角を開いたときだけ読み込む。1 ファイルの gist も同じ形にする。
- 上部の入力欄：入力すると、タイトル・説明文・ファイル名で即座に絞り込む。Enter を押すと GitHub の gist 検索（`user:<login> <語>`）へ移動する。
- ユーザー一覧や starred では、「Older」をたどって最大 10 ページ（100 件）を 1 つのリストにまとめる。それ以上ある場合は GitHub のページへのリンクを出す。検索結果と discover はまとめない。
- ファイル名は、行が画面に入ったときに読み込む（同時に 3 件まで）。localStorage に gist の日時と一緒に保存し、gist が更新されるまで使い回す。

## v3：プレビューを左右分割にする（2026-10-26 追記）

「Preview」ボタンは高さが約 16px で押しにくかった。Apple HIG では、マウス操作のコントロールは最小 20pt・推奨 28pt とされている。また HIG はリストについて「中身を行の中で広げるのではなく、選ぶと詳細ビューに出す」形（Mail / Finder のスプリットビュー）を勧め、選択中の行は常にハイライトするよう求めている。

- ボタンは廃止する。行のどこを押しても選択でき、右側の固定欄（sticky）に表示する。最初は先頭の行を選んでおく。
- ↑↓ キーで選択を移動する。Enter かダブルクリックで gist を開く。右欄の上にも「Open gist」ボタンを置く。
- 行のファイル名チップ、または右欄上部のファイルボタン（高さ 28px）を押すと、そのファイルを表示する。チップは Cmd+クリックで新しいタブに開ける。
- 幅 1011px 以下では右欄を出さず、行を押すと gist を開く。
